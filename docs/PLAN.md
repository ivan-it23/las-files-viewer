# Просмотрщик LAS-файлов с ИИ-агентом — план

Пользователи — интерпретаторы. Работают на своих рабочих станциях под Windows.
Из инфраструктуры доступен только хостинг (сайт horizon.ru); собственный сервер
компании используется как архив и для приложения не настраивается.

## Решения

| Вопрос | Решение | Почему |
| --- | --- | --- |
| Платформа | Настольное приложение WinUI 3 (.NET 10) | Хостинг не может выполнять Python и песочницу; повторно используется инфраструктура AMK-Data-Visualization |
| Данные и расчёты | Python-движок — дочерний процесс приложения | Скрипты агента пишутся на Python; LAS читается в одном месте, без двух расходящихся разборщиков |
| Связь UI ↔ движок | JSON-RPC через stdin/stdout | Нет открытого порта, время жизни движка привязано к приложению |
| Модели | polza.ai, OpenAI-совместимый `chat/completions` с `tools` | Уже используется в horizon.ru |
| Ключ polza.ai | Только на сайте; приложение ходит через посредника по токену пользователя | Как у реестра приборов в AMK; потоковая передача через PHP на хостинге уже работает в `AiAgentController::chatStream` |
| Скрипты агента | Выполняются локально, после подтверждения пользователем | Данные скважин не уходят дальше модели |

## Архитектура

```
┌──────────────────────────── Рабочая станция ─────────────────────────────┐
│ WinUI 3                                                                  │
│  ├─ Проект: скважины, файлы, кривые, шаблоны                             │
│  ├─ Планшет (Win2D): треки, шкалы, заливки, маркеры, курсор              │
│  ├─ Таблица данных, редактор заголовка, кросс-плоты, гистограммы         │
│  └─ Чат агента (WebView2: markdown, код, изображения, кнопки подтверждения)│
│           │ JSON-RPC (stdio)                                             │
│ Python-движок (встроенный Python, ставится установщиком)                 │
│  ├─ las_io: чтение/запись LAS 1.2/2.0/3.0, кодировки, отчёт о разборе    │
│  ├─ processing: фильтры, сдвиг, склейка, пересчёт шага, калькулятор, QC  │
│  ├─ agent: цикл вызова инструментов, контекст текущего вида              │
│  ├─ sandbox: подпроцесс, таймаут, отдельная папка, без сети              │
│  └─ reports: matplotlib + python-docx → DOCX/PDF                         │
└───────────────────────────────┬──────────────────────────────────────────┘
                                │ HTTPS + токен пользователя
                    horizon.ru: посредник /api/llm (SSE) ──► polza.ai
```

Движок владеет данными: UI получает кривые как массивы float32 по запросу.
Кривые, созданные агентом или обработкой, появляются в проекте как обычные
кривые с историей происхождения (формула, скрипт, исходные кривые).

## Что показали файлы скважины 3201 (Кийское, ИК прибор 004-2025)

- LAS 2.0, без переноса строк, кодировка **CP1251** без BOM; единицы кириллицей (`Омм`).
- Нестандартное имя секции `~Parametr information` — разборщик должен
  ориентироваться на первую букву после `~`.
- `NULL = -32768`, в данных записано как `-32768.00`.
- Секция `~Well` пустая (COMP, WELL, FLD…), а сведения о скважине лежат рядом
  в `config/3201.TXT` в кодировке **CP866**: месторождение, заказчик, исполнитель,
  оператор, даты, интервал. Нужен редактор заголовка с заполнением из этого файла.
- `3201 ИК.las` — объединение `400.las` и `2000.las` (фазы и УЭС на 400 и 2000 кГц,
  зонды 0.5–1.8 м), но на 1.7 м короче: 3032.64 против 3034.34.
- **Насыщение УЭС у верхнего предела преобразования (~6925–6996 Ом·м):**
  RO4_400_S — 58% отсчётов, RO3_400_S — 45%, RO4_2000_S — 22%. Проверка качества
  должна находить такие «полки» и помечать интервалы как недостоверные.
- В папке также: `.DEV`/`.if` (сырые кадры), `.gl1` (данные станции, спуск/подъём),
  `.IGP` (в т.ч. «увяз» — после увязки по глубине), `рапорт.xlsx`. Спуск и подъём
  есть отдельно — это основа проверки повторяемости.

## Функции просмотрщика (уровень современных аналогов)

### Данные и проект
- Чтение LAS 1.2 / 2.0 / 3.0, в т.ч. wrap; автоопределение кодировки
  (UTF-8 / CP1251 / CP866); терпимость к нестандартным секциям с отчётом о разборе.
- Запись LAS 2.0 / 3.0 (выбор кодировки), экспорт CSV / Excel.
- Проект: несколько скважин и файлов; дерево «скважина → файл → кривая».
- Редактор заголовка (~Well, ~Curve, ~Parameter), словарь мнемоник и псевдонимов,
  пересчёт единиц.
- Таблица значений с поиском, переходом к глубине и правкой.

### Планшет
- Трек глубины и произвольное число треков; линейная и логарифмическая шкала.
- Несколько кривых в треке: цвет, толщина, стиль, собственная шкала в шапке трека,
  перенос за шкалу (backup/wrap) для УЭС.
- Заливки: между кривыми, до значения, до края, градиентом, подсветка пересечений.
- Масштаб глубины (1:200, 1:500, 1:1000 …), плавная прокрутка и zoom.
- Курсор-читалка со значениями всех кривых на глубине.
- Перетаскивание кривых между треками, контекстное меню кривой.
- Маркеры, интервалы (пласты), текстовые пометки; хранятся в проекте.
- Шаблоны планшетов (JSON), готовые шаблоны под приборы: ИК 400/2000, АК.
- Несколько файлов рядом с синхронной глубиной: спуск/подъём, 400/2000, до/после обработки.
- Печать и экспорт планшета (PDF / PNG / SVG) со шапкой, длинные разрезы на несколько страниц.

### Обработка и анализ
- Калькулятор кривых (формулы), фильтры (скользящее среднее, медиана), удаление выбросов.
- Сдвиг по глубине (depth shift) с увязкой по опорной кривой, пересчёт шага, обрезка.
- Склейка (splice) интервалов из разных файлов.
- Ручная правка кривой «карандашом»; отмена/повтор; журнал изменений.
- Статистика по интервалу, гистограммы, кросс-плоты (с раскраской по третьей кривой).
- Контроль качества: пропуски, выбросы, насыщение/«полки», постоянство шага,
  повторяемость спуск/подъём, согласованность частот 400/2000.

## ИИ-агент

Цикл вызова инструментов на стороне движка; модель получает не весь файл,
а результаты инструментов. Агент видит текущий контекст: открытые файлы,
видимый интервал глубин, выбранные кривые.

| Инструмент | Что делает | Подтверждение |
| --- | --- | --- |
| `get_header` | Заголовок, кривые, единицы, NULL, диапазоны | нет |
| `curve_stats` | Статистика кривой на интервале | нет |
| `find_intervals` | Интервалы по условию (`RO2_400_S > 100`, насыщение, пропуски) | нет |
| `get_samples` | Значения с прореживанием | нет |
| `qc_report` | Сводка контроля качества | нет |
| `render_plot` | Картинка планшета/кросс-плота → модели (если модель принимает изображения) | нет |
| `add_markers` | Маркеры и интервалы на планшет | да |
| `create_curve` | Новая кривая по формуле | да |
| `run_python` | Скрипт с готовыми `las`, `df`; результаты — в папку отчёта | да, пользователь видит код |
| `build_report` | Отчёт DOCX/PDF по шаблону | да |

Удачные скрипты сохраняются в библиотеку и запускаются повторно без агента.
Системный промпт содержит описание приборов компании (мнемоники, частоты,
длины зондов, пределы преобразования) — берётся из документации AMK.

Модель выбирается в настройках из каталога polza.ai среди моделей с
поддержкой инструментов.

## Этапы

1. ✅ **Каркас** (0.1.0, 2026-10-02). Решение WinUI + модули, встроенный Python,
   JSON-RPC, установщик и автообновление по HTTPS. Каталог обновлений
   `https://amk-horizon.ru/downloads/las-viewer/` на сайте ещё не создан.
2. ✅ **Чтение и просмотр** (0.2.0, 2026-10-02). Разборщик LAS в движке с отчётом
   о разборе, дерево проекта, вкладки «Планшет», «Данные», «Заголовок»,
   «Сводка», планшет с треками, лог-шкалами, курсором, прокруткой и масштабом.
   Проверено на файлах скважины 3201. Заполнение заголовка из `config\3201.TXT`
   ждёт подтверждения раскладки этого файла.
3. **Полноценный планшет.** Заливки, шаблоны, маркеры, несколько файлов рядом,
   печать и экспорт.
4. **Обработка и QC.** Калькулятор, фильтры, сдвиг, склейка, кросс-плоты,
   гистограммы, проверки качества.
5. **Агент.** Посредник на horizon.ru; сначала инструменты только для чтения,
   затем `render_plot`, `create_curve`, `run_python`, отчёты.
6. **Развитие.** Библиотека скриптов и шаблонов отчётов, другие форматы (DLIS),
   обработка сырых данных прибора.
