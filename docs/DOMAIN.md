# Предметная область: LAS компании и GORIZONT

Что известно о данных, с которыми работает программа, и чего пока не
хватает. Основано на образцах скважин 3201 и 51 и на разборе программы
GORIZONT (2026-10-04…09). Догадки помечены как догадки: подтверждать их
должен интерпретатор или разработчики GORIZONT.

## Откуда берутся LAS-файлы

Прошивка прибора пишет сырые кадры (`.if`, `.DEV`, `.bin`, `.gl1`). Кривые и
LAS из них делает **GORIZONT** (`C:\AMKPrint\AMK_2007.exe`, 1.0.11.25,
Borland C++ Builder) — система первичной обработки приборов АМК:
преобразование данных около 60 приборов (ЭМК, ВИКИЗ, АК, ГГКп, НГК/ННК, СГК
и др.), расчёты по методам, заключения в Word, готовые планшеты.

**Вывод для программы:** преобразование данных приборов не дублируем — оно
остаётся в GORIZONT. Просмотрщик начинает работу с его LAS. Код прошивки не
нужен.

Список кривых в конкретном LAS складывается из трёх источников:
1. **Преобразование прибора** (меню «Файл → Преобразование…»: EMK, EMK2,
   EMK SA, EMK AF, VIKIZ, AKL…) — фиксированный набор мнемоник. Имена зависят
   от версии преобразования: у скважины 3201 ЭМК — `RO1_400_S`, у скважины 51
   те же величины — `RO1_PH_04_S`.
2. **Обработка** (меню «Обработка») добавляет расчётные кривые: `Wnnk`,
   плотность, интервальное время, абсолютная глубина. Часть кривых
   интерпретатор создаёт и называет сам.
3. **Выбор при сохранении** («Выделите кривые»): поэтому у скважины 51 —
   файл на метод, а у 3201 — ещё и общий `3201 ИК.las`.

Закрытого списка всех кривых нет и не будет. Схема программы: **словарь
известных кривых компании + корректная работа с неизвестными** (читаются и
рисуются с автошкалой, но без шаблона, QC и подсказок агента).

## Фактический формат LAS (по скважинам 51 и 3201)

| Что | Как сейчас |
| --- | --- |
| Версия | LAS 2.0, без переноса строк. GORIZONT умеет и 1.2 |
| Файлы | Скважина 51: один файл на метод (10 файлов). Скважина 3201: по файлу на частоту и общий |
| Кодировка | Скважина 51 — CP866 (по умолчанию в GORIZONT), скважина 3201 — CP1251; в файле не указана |
| Секции | `~Version`, `~Well`, `~Curve`, `~Parametr information` (с опечаткой, пустая), `~Other` (пустая), `~ASCII` |
| Глубина | Метры, шаг 0,1 м. Каждый файл начинается со своей глубины (279,77, 301,22, 305,52…), общей сетки нет |
| NULL | -32768, в данных `-32768.00` |
| Сведения о скважине | COMP — заказчик, WELL, FLD, CTRY = Россия, SRVC обрезан до «АМК ГОРИЗОН», DATE вида `08-09.01.2021`; LOC, CNTY, STAT, API пустые. У ДС и у скважины 3201 раздел пуст целиком |
| Кривые | Мнемоники латиницей и кириллицей (`ГГКп_мз`, `Давление`, `НОМИНАЛ`). Единица часто пустая и указана только в конце описания (`…, Ом*м`); встречается «Oмм» с латинской O. Описания — из словаря `Work\Remarka.ini` |
| Параметры | Конструкция скважины и раствор в LAS не попадают, хотя в форме сохранения GORIZONT такие поля есть |

### Скважина 3201 (Кийское, ИК прибор 004-2025, каротаж в процессе бурения)
- `400.las`, `2000.las` — фазы и УЭС на 400 и 2000 кГц, зонды 0,6/1,0/1,4/1,8 м
  и 0,5/0,9/1,3/1,7 м (по описаниям; не опечатка ли — вопрос);
  `3201 ИК.las` — их объединение, но на 1,7 м короче (3032,64 против 3034,34).
- **«Полки» УЭС у предела преобразования ~6925–6996 Ом·м:** RO4_400_S — 58%
  отсчётов, RO3_400_S — 45%, RO4_2000_S — 22%. Основной пример для QC.
- Сведения о скважине — в `config\3201.TXT` (CP866), раскладка строк не
  подтверждена (догадки — в ТЗ и в истории; не использовать до ответа).
- Рядом: `.DEV`/`.if` (сырые кадры), `.gl1` (станция, спуск/подъём), `.IGP`
  (в т.ч. «увяз»), `рапорт.xlsx`.

### Скважина 51 (Узеньское, каротаж на кабеле)
- 10 LAS: ЭМК, ВИКИЗ, АК, ГГК-П, РК, КС, ДС, ИНКЛ, резистивиметр, термометр
  с давлением. Все открываются разборщиком без ошибок.
- Два планшета: оперативный со станции `51_Планшет_(ЭМК_ВИКИЗ).BMP` (сделан
  в GORIZONT «Сохранить как рисунок», линейные шкалы 0–10) и итоговый
  `51_Узеньская_ЭМК.BMP` (лог-шкалы 0,1–46,4, подробная шапка, колонки
  «Стратиграфия», «Литология», «Насыщение», абсолютная глубина).
- Противоречия: заказчик в LAS «ООО ПГК», на итоговом планшете «ОАО НК
  Янгпур»; на планшете скважины глубиной ~910 м интервал кавернометрии
  3669–4180,9 м — похоже, от другой скважины.
- АК: `Tp1`, `Tp2` (время пробега, мкс), `dTp` (интервальное время, мкс/м, в
  описании «мкс»), `Ap1`, `Ap2` (амплитуда, мВ только в описании), `Alfa` (без
  описания, вероятно затухание дБ/м).

## GORIZONT: как работает с LAS и планшетами

- LAS открывается через «Импорт» с выбором кривых галочками.
- Кодировка — один ручной переключатель «Вид → Кодировка LAS-файла:
  DOS/WINDOWS», автоопределения нет (при неверном выборе «мкс» → «¬Єб»).
- Сохранение в LAS: версия 1.2/2.0, глубина в см или футах, квантование 10
  или 20 см, кодировка (по умолчанию DOS). Шапка — из формы «О скважине».
  Все кривые сводятся на сетку глубин первого файла.
- Справочники в `C:\AMKPrint\Work\`: `Remarka.ini` (79 параметров по 11
  приборам: мнемоника, описание, единица; нет ЭМК `RO*_PH_*`, у фаз `F*_400_S`
  единица «рад», а в LAS 3201 — «grad»), `D_names.txt` (накопленные имена
  кривых, GORIZONT дописывает его сам), `Mnemonics.txt`, `StrihKod.txt`
  (77 модулей приборов).
- Планшет: шаблон колонок `.SAB` (только ширины), собранный планшет `.PLN`;
  на ПК пользователя есть только «Чистый планшет». Типы колонок: глубина,
  диаграмма, литология, коллектор, насыщение, ярус, система, кривая-пласт,
  объёмная модель, ФКД, ВАК, профиль, спектр. Глубина внутри — в сантиметрах.
- Свойства кривой: шкала «единиц на см», лог-шкала, «автоматический сдвиг
  шкалы» (перенос), цвет, тип линии; заливки от кривой, границ, по пластам,
  в коридоре, с узорами литологии.
- Операции: сдвиг по глубине/амплитуде, растяжение/сжатие, сглаживание,
  обрезка, склейка по точке, интерполяция, фильтры нулей/сбоев/медианный,
  гистограмма, корреляция, увязка, правка «карандашом» и «ластиком».
  Формулы — только из списка.

**Чего в GORIZONT нет — ниша программы:** автоматический QC («полки»,
выбросы, повторяемость; есть только для инклинометрии), автоопределение
кодировки, кросс-плоты, проект на несколько скважин, ИИ-ассистент.

## Смысл кривых

Чтение LAS универсально и уже готово. Смысл кривых — нет: мнемоники не
стандартизированы. Шаблоны планшета, QC (предел ~7000 Ом·м есть у ЭМК и нет
у ВИКИЗ), заполнение единиц и агент опираются на **словарь**: мнемоника →
метод, прибор, величина, единица, зонд/частота, допустимые пределы, сырая
или расчётная. Основа — `Remarka.ini`, но он неполный.

Массивные данные (волновые картины ФКД/ВАК, развёртки профилемера) в модель
«столбец = кривая» не ложатся; пока не нужны.

## ВИКИЗ по методическому руководству (2026-10-13)

Пользователь предоставил эталон компании — «Технология исследования
нефтегазовых скважин на основе ВИКИЗ» (ред. Эпов, Антонов, 2000); по его
словам, интерпретация в компании совпадает с ним примерно на 90 %. Знания
разложены по карточкам `engine/lasviewer_engine/knowledge/vikiz/*`. Что
из этого закрывает вопросы:

- **Зонды ВИКИЗ:** 0,5; 0,7; 1,0; 1,4; 2,0 м (табл. 4.1); в мнемониках
  компании (`IK05…IK20`, `RO05…RO20`) цифры — длина в дециметрах.
- **Пределы ВИКИЗ:** достоверная Δφ — от 0,2° до ≈ 90° (≈ 0,22 Ом·м), с. 62.
  В `51_ВИКИЗ.las` Δφ < 0 на 0,2–6 % записи (в основном 315–360 м), и ровно на
  этих отсчётах ρк = 1000 Ом·м — **похоже на предел пересчёта в GORIZONT**
  (догадка, подтвердить у разработчиков GORIZONT).
- **Брак ВИКИЗ:** шаг ≤ 0,2 м, скорость ≤ 2000 м/ч, калибровка 0/25° ± 0,2°,
  повторный замер ≤ 3 % (два длинных) и ≤ 5 % (три коротких), с. 58–59.
- **Порог «без изменения» между зондами:** берётся из погрешностей
  методички (Δφ 3 / 4 / 2 / 2 / 2 %, усиление при пересчёте в ρк 1,3–2,0) —
  `vikiz.classify`.
- Для **ЭМК** применимость не подтверждена — карточка `emk/primenimost`
  (черновик): переносится только качественный принцип радиального
  зондирования.
